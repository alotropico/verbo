# Verbo acceptance catalog

Version 2 — 2026-10-22. These are manual recipes, not a playback runner. A passing unit test or direct Alo invocation does not establish composer-to-model acceptance.

## Prerequisites and evidence

Use a private snapshot of the real built main, preload, renderer and matching standalone Alo bundle. Preserve dirty source trees before changes. Never build underneath a personal instance or source watcher. Give the test instance absolute, separate userData, sessionData, settings, attachments and Alo profile locations before importing main. Set all three Alo runtime overrides together. `VERBO_HIDDEN_TEST_ROOT` enables the development-only hidden presentation mode; its user-data, session-data and alo-profile children must match the launcher configuration. Production behavior is unchanged when it is absent.

Use an instance-scoped Electron driver for the normal composer, navigation, queue, Stop and approval cards. Keep context isolation, sandbox and IPC validation. Never use desktop input, clipboard, global captures, personal profiles, mocked model replies or direct action calls as acceptance. Capture only the test webContents. Suppress taskbar attention, sound, voice acquisition and native dialogs. Reject visible external effects. A launcher restart must ignore previously issued driver requests.

Use one real local Ollama request at a time. Record installed model digest, service version, chat settings, effective per-role overrides/timeouts, instructions/guidance identity, app/bundle digests and process ownership. Reuse shared services without restarting or stopping them. A chat title alone is not an identity.

Every attempt records exact resolved prompts, fixture manifest, independent before/after observations, chat/message/turn/receipt IDs, saved completion state, final reply and verdict. Keep first failures when rerunning. Separate task outcome, command coverage, backend effect, report correctness and command-name assistance. A completed queue or stream alone does not prove the canonical assistant message saved successfully.

## Small fixture recipes

Use deterministic UTF-8 bytes and store hashes/nonces outside model context. Ownership markers and absolute roots belong in the local manifest. Avoid instruction entry filenames and dot-directories in temporary campaign material.

- F01: `alpha.txt = "alpha\n"` (6 bytes), `data.json = "{\"n\":7}\n"` (8), `nested/beta.md = "# Beta\n"` (7). Three files, one descendant directory, 21 content bytes, one txt/json/md file each.
- F02: five text filenames containing the same unique stem; each file contains a distinct tiny line, one with a unique content-search marker. Do not generate a large tree merely to exercise pagination.
- F03: `first\ncafé second\nthird: 42\nlast\n`; JSON object with a random `tracking.id`. Compare the exact returned line range and pointer value, and hash both files before/after.
- F04: two identical small files and one single-line variant. Compute SHA-256 with an independent local filesystem tool before prompting.
- F05: retain a fixed 1×1 PNG and its known SHA-256 in the recipe/evidence. Request metadata without image payload unless vision coverage is explicitly intended.
- F06–F10: separate directories with fully resolved endpoints. Existing edit source is `draft\n`; create content is literal user input. Keep a full bounded filename/hash inventory before each mutation and approval.
- F11: two independently seeded disposable files, no other targets. Retain denied fixture and native receipt evidence; do not attempt trash undo.
- F12: fresh missing target; nonexistent alias; an escape expression whose attempted destination is still a known owned path; independent RO source/attempted new target. Verify complete bounded trees afterward.

For unchanged read fixtures, compare SHA-256 and byte length against the manifest. For mutations, verify the whole owned subtree, not only the expected output. Before every delegated approval, match actual operation/diff/resources to the case manifest, recheck unchanged bytes, verify absolute containment and non-link ancestry, then click the normal card. Unexpected targets or broadened effects require human clarification.

## Closure

Keep natural first-pass outcomes separate from recovered/assisted results and backend success. Rebuild/restart only the campaign after main/preload changes; never replay unsettled effects. Limit each issue to two focused diagnosis/fix cycles after its initial failure. Preserve exact unresolved next actions in the resume index.

On the stable final build repeat three safe representative cases once with fresh chats/fixtures; record variation without statistical claims. Run repository tests, typecheck, lint, build and scoped non-writing formatting checks appropriate to actual fixes. Do not perform broad formatting cleanup. Final report includes all verdict counts, every command's readiness/blocker, model identity/settings and candid usability, invalid/duplicate attempts, reporting defects, fixes, checks and retained fixtures. Cleanup affects only manifest-owned contained paths and PID/creation-time-verified campaign processes after quiescence.
