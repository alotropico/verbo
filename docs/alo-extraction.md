# Alo command extraction

Verbo delegates domain commands and command settings to the independent Alo CLI. The retained catalog has 45 commands across Environment, Memory, Files, Projects, Software, AGS and Obsidian. The old Verbo engine and Web module are removed. Existing Ollama tools remain `capabilities.list`, `capabilities.search`, `capabilities.describe` and `actions.invoke`.

Build with standalone Node.js 24 or newer. Keep the Alo source checkout beside Verbo for development packaging, install Alo's dependencies once, and run `pnpm alo:prepare`. `pnpm build` prepares Alo automatically. The packaged app includes its own Node/Alo pair under `resources/alo` outside asar; normal runtime does not require a neighboring checkout or PATH resolution.

`VERBO_ALO_NODE`, `VERBO_ALO_ENTRY` and `VERBO_ALO_PROFILE` select three explicit absolute paths for isolated testing/development. Partial configuration fails closed. Without overrides, development uses the prepared resource folder and Windows packaging uses `process.resourcesPath`. Command storage defaults to `%APPDATA%/alo/alo.sqlite`.

Verbo's `verbo.sqlite` contains app, conversation, workflow, queue, voice and upload metadata. Alo owns Memory, scopes, project/application registrations, integration settings, aliases, receipts, queries and operation plans. App uploads remain in Verbo. The bridge carries only necessary trusted caller/thread/policy/correlation information; model arguments cannot supply it. Command-setting screens use RPC adapters, and workflow attempts correlate with owner receipts by ID.

The current app schema is version 24. Opening an old or foreign profile refuses it before schema/backup writes and stops startup. An existing v23 profile needs the verified one-time partition; it is not silently upgraded at app launch.

The sibling Alo repository provides `scripts/cutover-verbo.cjs`. Supply absolute `--verbo`, `--alo` and `--backup` paths. Default mode creates a consistent DB/assets backup, staged Alo database and manifest without changing the live profile. After isolated packaged-app acceptance, `--commit` checks source rows and manifest hashes under an exclusive transaction, refuses overwrite or changed data, verifies app preservation, and partitions the command tables. Keep all backups. Old previews/query cursors expire; interrupted effects are never automatically replayed. A failed/published profile is retained for inspection.
